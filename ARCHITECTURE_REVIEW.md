Generated: 2026-08-30T21:10:47.883Z

## Summary
The codebase is well-documented and follows a clear pre-built-component philosophy (Card/ScreenScaffold/SummaryHero/etc.) with consistent SDK-guard error handling, but it carries real architectural debt: a stale/parallel type-contract file that conflicts with the real domain types, an entire leaderboard engine that appears to be dead code superseded by a different implementation, and the same small utility snippets (haptic wrapper, safe price lookup, disclaimer text) copy-pasted across many files instead of shared. No circular imports were found in the reviewed files. Addressing the duplicated type sources and consolidating the repeated wrapper functions would meaningfully improve maintainability.

## Issues
### Critical
- [duplication] Core domain types (RouteState, Instrument, Trade, User, Portfolio, BacktestResult, QuizResult) are declared twice with incompatible shapes: once in src/lib/contract.ts (stale 'auto-generated spec' artifact) and once in src/lib/types.ts (the actually-implemented shapes). App.tsx imports RouteState from contract.ts (`{pathname, params, state}`) while pages import a completely different per-route RouteState map from lib/types.ts, so the 'contract' no longer matches reality. — Files: src/lib/contract.ts, src/lib/types.ts, src/App.tsx, src/pages/Portfolio.tsx / Fix: Delete contract.ts (or clearly mark it archived/non-authoritative) and make lib/types.ts the single source of truth; update App.tsx's RouteState import accordingly.
- [dead_code] lib/leaderboard.ts implements a full deterministic bot-seed/ranking engine with its own LeaderboardEntry shape ({id, nickname, isMe, isFriend, totalAssetKrw, returnPct, streak}), and is re-exported through lib/quiz.ts, but the actual Leaderboard page reads seed data via storage.loadLeaderboardSeed() with a different shape ({userId, userName, score}), and contract.ts defines yet a third shape ({rank, user, score}). This strongly suggests lib/leaderboard.ts (132 lines) is unused/superseded code left in the tree. — Files: src/lib/leaderboard.ts, src/pages/Leaderboard.tsx, src/lib/quiz.ts, src/lib/contract.ts / Fix: Confirm which leaderboard implementation is actually live; delete the unused one and its re-export, and unify on a single LeaderboardEntry type in lib/types.ts.

### Suggestions
- [consistency] Import path convention is inconsistent: src/App.tsx, src/components/*, and src/lib/checkin.ts use the '@/' alias, while nearly every file under src/pages uses relative '../' imports for the same modules. — Files: src/pages/Backtest.tsx, src/pages/Home.tsx, src/pages/Market.tsx, src/pages/Portfolio.tsx, src/pages/Trade.tsx, src/pages/Leaderboard.tsx, src/pages/Quiz.tsx, src/pages/QuizResult.tsx, src/pages/BacktestResult.tsx / Fix: Standardize on the '@/' alias everywhere (or add a lint rule enforcing it) so import style doesn't vary by directory.
- [duplication] Amount.tsx and CountUp.tsx both re-implement the same wrapping <span> (display:inline-block, nowrap, tabular-nums) plus formatNumber+unit rendering; only the animation logic differs. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Extract the shared nowrap/tabular-nums span markup into one internal NumberDisplay component that both Amount and CountUp compose.
- [dead_code] Several exports appear unreferenced by any page shown in the codebase: lib/utils.ts's `cn`, `formatCurrency`, and `formatDate`, and the components TossPurchase.tsx and TossRewardAd.tsx (IAP / rewarded-ad wrappers) are not imported by Home, Market, Trade, Portfolio, Backtest, BacktestResult, Quiz, QuizResult, or Leaderboard. — Files: src/lib/utils.ts, src/components/TossPurchase.tsx, src/components/TossRewardAd.tsx / Fix: Verify these are genuinely used elsewhere (e.g. a monetization screen not shown); otherwise remove them or clearly document them as an intentionally-unused pre-built library pending wiring.
- [naming] ListSkeleton accepts two aliased props (`rows` and `count`) for the same concept explicitly 'because call sites disagree,' papering over inconsistent naming at call sites rather than resolving it. — Files: src/components/LoadingSkeletons.tsx / Fix: Pick one prop name (e.g. `rows`, matching LoadingState's convention), update all call sites, and drop the alias.
